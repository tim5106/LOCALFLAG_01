# 1주차 통합 완료 기준

## 통합 흐름

```text
TourAPI 종로구 데이터
  → 백엔드 정규화 API
  → 프론트엔드 API 호출
  → Kakao 지도 마커
  → 마커 클릭 시 장소 정보 표시
```

## 백엔드 담당 완료 기준

- [ ] `areaCode=1`, `sigunguCode=23`으로 종로구 데이터를 조회한다.
- [ ] 유효한 관광지 10개 이상을 반환한다.
- [ ] `mapy`를 위도, `mapx`를 경도로 숫자 변환한다.
- [ ] 빈 문자열을 `null`로 정규화한다.
- [ ] 제목·좌표가 잘못된 데이터는 제외한다.
- [ ] 응답 필드는 `TOUR_API_MAPPING.md`와 일치한다.
- [ ] 응답에 `meta.source="tour-api"`를 포함한다.
- [ ] 실제 응답 예시를 프론트엔드에게 전달한다.
- [ ] 외부 API 오류, 데이터 없음, 서버 오류를 공통 오류 형식으로 반환한다.

## 프론트엔드 담당 완료 기준

- [ ] Kakao JavaScript 키와 개발 도메인을 설정한다.
- [ ] 첫 화면이 종로구를 중심으로 열린다.
- [ ] 백엔드 데이터 10개 이상을 마커로 표시한다.
- [ ] `lat`, `lng` 위치가 장소와 일치하는지 표본 3개를 확인한다.
- [ ] 마커를 누르면 이름·주소·이미지가 표시된다.
- [ ] 이미지가 없거나 깨졌을 때 대체 이미지를 표시한다.
- [ ] 로딩·오류·검색 결과 없음 상태를 표시한다.
- [ ] 실제 데이터와 fallback 데이터를 화면 또는 개발 로그에서 구분한다.
- [ ] 모바일 폭에서 지도와 정보 카드가 잘리지 않는다.

## UI/UX 담당 완료 기준

- [ ] 기본·선택·인증 불가 마커 상태를 정의한다.
- [ ] `AREA` 장소가 단일 지점처럼 오해되지 않는 표현을 정의한다.
- [ ] 모바일 하단 정보 카드의 레이아웃을 전달한다.
- [ ] 긴 장소명·긴 주소·이미지 없음 상태를 설계한다.
- [ ] 로딩·오류·결과 없음 상태의 문구와 화면을 설계한다.
- [ ] 여백, 글자 크기, 이미지 비율, 카드 높이 등 구현 수치를 명시한다.

## 팀장 완료 기준

- [ ] MVP 결정 문서와 데이터 계약을 팀에 공유한다.
- [ ] `data/jongno_mvp_spots.csv`에 후보 10개 이상을 채운다.
- [ ] 각 후보를 `POINT`, `AREA`, `EXCLUDE`로 분류한다.
- [ ] 접근 가능 여부와 좌표가 실제 입구를 가리키는지 확인한다.
- [ ] 백엔드 응답과 프론트엔드 사용 필드가 일치하는지 확인한다.
- [ ] 실제 API 데이터임을 확인하고 통합 시연을 진행한다.
- [ ] 미완료 항목을 담당자·기한과 함께 다음 작업으로 등록한다.

## 회의 종료 전 시연 순서

1. 백엔드가 종로구 목록 API 응답을 보여준다.
2. 프론트엔드가 같은 응답으로 카카오 지도를 연다.
3. 마커 수와 API `meta.count`가 일치하는지 확인한다.
4. 임의의 마커 3개를 눌러 이름·주소·이미지를 확인한다.
5. 이미지 없는 장소와 오류 상태를 각각 한 번 시연한다.
6. 팀장이 통과·미통과 항목과 다음 담당자를 기록한다.

## 이번 회의에서 제외하는 기능

- 회원가입·로그인
- GPS 방문 인증과 부정 이용 방지
- 포인트 원장과 지급 트랜잭션
- 랭킹·배지·소셜 기능
- 전체 서울 또는 전국 확장
